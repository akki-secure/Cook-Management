# 要件定義書: パスワードリセット機能

## 背景・目的

現状、ログイン中のユーザーが自分でパスワードを変更する機能(マイページ編集)はあるが、**パスワードを忘れてログインできなくなった場合に、自力で復旧する手段がない**。この状態を解消するため、「パスワードをお忘れの方」向けのリセットフローを追加する。

## スコープ

### 含むもの

- ログイン画面からの「パスワードをお忘れですか?」導線
- メールアドレスを入力してリセット用リンクを送信するフォーム
- メール内のリンクから新しいパスワードを設定するフォーム
- 開発環境でのメール送信確認手段(letter_opener)

### 含まないもの(対象外)

- 本番環境向けのSMTP設定(ENV変数での設定余地だけ残し、実設定は別対応)
- 2段階認証・SMS等の代替認証手段
- パスワード強度メーター等のUI強化(既存の「8文字以上」制約のみ踏襲)

## 利用者フロー

1. ユーザーがログイン画面で「パスワードをお忘れですか?」をクリック
2. メールアドレス入力画面が表示される
3. 登録済みのメールアドレスを入力して送信
4. どのメールアドレスでも(登録の有無によらず)「送信しました」という同じ内容のメッセージが表示される(下記「セキュリティ要件」参照)
5. 該当ユーザーが実在する場合のみ、そのメールアドレス宛にリセット用リンクを含むメールが送信される
6. ユーザーがメール内のリンクをクリックすると、新しいパスワードの設定画面が開く
7. 新しいパスワードと確認用パスワードを入力して送信
8. 成功すると、ログイン画面にリダイレクトされ「パスワードを再設定しました。ログインしてください。」と表示される
9. 新しいパスワードでログインできる

## 画面一覧

| 画面 | URL | 説明 |
|---|---|---|
| パスワードリセット申請 | `/password_resets/new` | メールアドレス入力フォーム |
| 新パスワード設定 | `/password_resets/:token/edit` | 新パスワード・確認用パスワード入力フォーム |

## 機能要件

### リセットリンクの発行(申請フォーム送信時)

- 入力されたメールアドレスに一致する登録済みユーザーがいる場合のみ、リセット用メールを送信する
- ユーザーの有無にかかわらず、画面には同じ成功メッセージを表示する(後述のセキュリティ要件のため)

### リセット用トークン

- 有効期限: **30分**
- 1回のパスワード変更で自動的に失効する(トークン発行後にパスワードが変わった場合、そのトークンはもう使えない)
- DBに専用カラムを追加しない方式(Rails標準の`generates_token_for`機能を利用)

### 新パスワード設定

- 新パスワードは既存のバリデーションと同じ(8文字以上)
- パスワードと確認用パスワードが一致しない場合はエラーを表示し、同じ画面に留まる
- トークンが無効(期限切れ・改ざん・使用済み)な場合は、リセット申請画面にエラーメッセージ付きでリダイレクトする

## セキュリティ要件

- **ユーザー列挙(enumeration)対策**: メールアドレスが登録されているかどうかによって画面の表示を変えない。登録されていないメールアドレスを入力した場合でもエラーにはせず、登録されている場合と同じ成功メッセージを表示する。
  - トレードオフ: メールアドレスを間違えて入力した場合でも「間違っている」というフィードバックが得られない。実害(スパム登録攻撃者によるメールアドレス調査)を防ぐことを優先する。
- リセット用トークンはURLに含まれる形で送信されるため、メールの盗み見や共有PCでのメール閲覧に注意が必要(一般的なメールベースのパスワードリセットに共通する制約として許容する)。
- パスワードそのものは既存同様 `has_secure_password`(bcrypt)でハッシュ化して保存し、平文では扱わない。

## 開発環境でのメール確認方法

- `letter_opener` gemを導入し、開発環境で送信されたメールは自動的にブラウザの新しいタブで開かれる形で確認できるようにする。
- 本番用のSMTP設定は対象外とし、`config/environments/development.rb` に本番設定は「TODO: 本番はENV経由でSMTP設定」というコメントのみ残す。

## 非機能要件

- 既存の画面デザイン(`.form-group` / `.btn` / `.error-messages` / パスワード表示切り替えボタン)を踏襲し、新規CSSは追加しない
- 日本語UI・日本語エラーメッセージで統一する
- 既存のテストスタイル(Minitest、fixtures、`sign_in_as`ヘルパー)に沿ったテストを追加する

## 受け入れ条件(Acceptance Criteria)

- [ ] ログイン画面から「パスワードをお忘れですか?」経由でリセット申請画面に到達できる
- [ ] 登録済みメールアドレスでリセット申請すると、letter_openerでメールが確認でき、本文にリンクが含まれる
- [ ] 未登録メールアドレスでリセット申請しても、登録済みの場合と同じ成功メッセージが表示され、メールは送信されない
- [ ] メール内のリンクから新パスワード設定画面に遷移できる
- [ ] 新パスワードを設定すると、ログイン画面にリダイレクトされ、新パスワードでログインできる
- [ ] 期限切れ(30分経過)または無効なトークンでアクセスすると、リセット申請画面にエラーメッセージ付きでリダイレクトされる
- [ ] トークン発行後にパスワードが変更された場合、そのトークンは無効になる
- [ ] 全自動テストがパスする
